B1. THE BLOCKER, MEASURED AND RESOLVED
--------------------------------------
The phase was gated on: does a synth_precomp_v1 record carry an athlete_id and
a day-offset within the pre-competition window?

MEASURED ANSWER (all 4,000 records, plus interim and silver layers):
  * day-offset: YES. time_to_competition_days in {0,1,2,3,5,7,10,14,21,30},
    counts 535/814/534/531/237/281/276/279/263/250.
  * athlete_id: NO. It exists nowhere. synthetic.py::_draw_stratum draws sport,
    competition_level, region, source_type, time_to_competition_days and
    training_load_hint INDEPENDENTLY per record. RawRecord has no subject
    field. extra == {} in all 4,000 records. No athlete_id / subject_id /
    speaker_id / participant_id anywhere in data/ or src/.

So every v1 record is an i.i.d. draw. v1 contains no panels, and no grouping of
it can produce a within-athlete series.

A SECOND blocker was already on record and applies with equal force. Phase 36
(.claude.md sec.19.3) measured that generate_scenario_record uses `timing` for
exactly two things -- the record id and time_to_competition_days -- so the text
is byte-identical across all three timings, spread 0.0000. Identity alone would
therefore have produced a slope fitted over noise, and the shuffled-time
control would have found nothing: a tautology, not a finding.

RESOLUTION (owner decision, 2026-09-29): build synth_precomp_v2 as a SEPARATE
ADDITIVE panel corpus with both an identity axis and a planted drift. v1 frozen
and untouched. Retrofitting identity onto v1 was proposed and REFUSED: assigning
i.i.d. draws to invented athletes manufactures panel structure that was never
generated, and a slope fitted across records whose sport, level and region all
change between "timepoints" is .claude.md sec.12.3 by a new door.

B2. THE DRIFT CLAIM (OWNER DECISION, 2026-09-29)
------------------------------------------------
Encoded into the generator, and therefore an owner decision under .claude.md
sec.8 rule 2, not a coding one:

    Approaching a competition, SOMATIC anxiety rises -- sharply in the final
    24-48h. COGNITIVE anxiety stays comparatively flat across the
    pre-competition window. SELF-CONFIDENCE stays flat.

Grounding: multidimensional anxiety theory's time-to-event prediction
[Martens1990], CSAI-2 tradition [Cox2003]. Both keys resolve in paper/refs.bib
and both are already the instrument_anchor config/taxonomy.yaml gives
cognitive_anxiety and somatic_anxiety generally, so the table is grounded in the
same instruments those constructs already cite -- the convention Phase 30
(sec.15.3) established for SCENARIO_BIAS.

BINDING FRAMING FOR THE PAPER: every trajectory number is a SANITY CHECK that
the analysis recovers a drift this project planted on purpose. It is not
evidence about athletes, not a clinical finding, and not support for the
psychological claim itself. Recovering a planted label is circular as evidence,
exactly as docs/data_sources.md already says of generation_spec.

All eleven channels behaved as the generator's design predicts.

Time axis: t = -time_to_competition_days, so t increases towards the event and a
POSITIVE slope means "rises as the competition approaches". Stated on every
surface that prints a slope, because fitting against the raw countdown gives a
negative coefficient for a rising quantity and that is the classic sign error
here.

B5. KEY DECISIONS
-----------------
1. athlete_id and timepoint_index live in record.extra, NOT as new RawRecord
   fields. Adding a field changes to_dict()'s key set for every record in the
   project including the hash-pinned v1 artefacts. extra is the schema's
   documented slot, so the panel corpus costs no reproducibility hash.
2. New module rather than editing scenarios.py or synthetic.py, so Phase 30's
   determinism tests and every seeded v1 artefact stay valid. Also avoids the
   ~10 CPU-hour corpus regeneration sec.18.3 prices.
3. Drift split across BOTH plant-probability and intensity, so no single
   timepoint is a giveaway and "rises sharply" means more athletes reporting it
   AND reporting it more strongly.
4. cognitive_anxiety and self_confidence declared in FLAT_BY_DESIGN as explicit
   negative controls, so the prediction is auditable in code rather than
   asserted in prose after the fact.
5. risk_index kept in its own category (inherits_drift) rather than listed
   beside the planted channel. It moves because somatic_anxiety carries +1.0 in
   LinearRiskScorer, so it is arithmetically downstream of the same planted
   effect -- a derived result is not an independent confirmation.
6. Ragged panel lengths (70% get 4-6 timepoints, 30% get 2-3), and PanelSpec
   REFUSES bands that do not straddle MIN_TIMEPOINTS_FOR_SLOPE, so the
   suppression rate is a measured number rather than 0% or 100%.
7. Clustering runs over the z-scored (slope, volatility, last_day_delta) vector,
   not raw series: the panels are ragged by design, so two athletes sit on
   different day sets and cannot be compared point-by-point without
   interpolating readings nobody took.
8. Unreadable timepoints are EXCLUDED from every series -- not imputed, not
   carried forward, not entered as 0.5. AthleteSeries refuses a value it did not
   earn, the same construction-time rule SquadMember, SentenceBand and CloudLane
   already enforce.

B6. THREE DEFECTS FOUND AND FIXED DURING THE BUILD
---------------------------------------------------
Recorded because each was silent and each would have shipped.

(a) CUE-BIASED TEMPLATE SELECTION REACHING A CORPUS. The first draft imported
    scenarios._realise_graded_at to plant the drift. That function biases
    template choice towards realisations containing
    src.evaluation.baselines.CONSTRUCT_CUES phrases -- legitimate for the
    Match-day demo, fatal for a corpus, because text chosen BECAUSE the lexicon
    detects it inflates the lexicon's own score. That is OPEN-021 made strictly
    worse by construction. Caught by
    tests/test_scenarios.py::test_no_corpus_writing_module_imports_scenarios,
    which exists for exactly this and whose docstring says the failure is
    silent. FIXED: temporal.py now imports nothing from scenarios.py and uses
    synthetic._realise plus a local _realise_graded_unbiased, both flat
    randrange over the bank with no cue list consulted. The corpus was
    REBUILT. Honest cost, paid rather than engineered away: detection fell, so
    unreadable records and suppressed slopes both rose. A test in
    tests/test_temporal.py now asserts the containment from this module's side
    too, so the reason travels with the code that broke it.

(b) NO MULTIPLICITY CORRECTION. Eleven channels were being tested
    simultaneously against a fixed 0.05. Across eleven channels that produces a
    false positive roughly half the time, and it duly did: coping_style reached
    an uncorrected p = 0.025 with no drift planted in it. Checked for a
    mechanism before correcting -- coping_style's mean probability is flat
    across the window (0.13-0.27, no trend) and its cue list shares ZERO terms
    with somatic_anxiety's -- so chance is the explanation. FIXED: Holm
    step-down across the channel family (FAMILY_ALPHA = 0.05). coping_style does
    not survive it. The correction was the right test whatever came out; it is
    not a response to the result, and reports/temporal.md says so and names the
    false positive rather than hiding it.

(c) IRREPRODUCIBLE PERMUTATION NULL. The control seeded numpy from
    hash((seed, channel)). Python randomises string hashing per process unless
    PYTHONHASHSEED is set, so the null differed between runs while looking
    seeded. FIXED: zlib.crc32 of the channel name. Verified identical across
    three fresh processes, and a test asserts run-to-run reproducibility.

Also: the scalar control was 11 channels x 2,000 permutations x ~300 series of
OLS fits and took minutes. Vectorised (with t centred, the slope reduces to
dot(t_c, y)/sum(t_c^2), so a whole permutation block is one matrix product).
Whole pipeline now runs in ~37s.
