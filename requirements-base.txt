# Base (light) dependency layer.
#
# Everything needed to run the agent orchestration, the config/taxonomy layer,
# the classical baselines, the dashboard shell, and the dev toolchain.
# Deliberately EXCLUDES torch/transformers — see requirements-ml.txt.
#
# Rationale (Phase 2 fix, 2026-08-09): installing torch from the default PyPI
# index on Linux pulls the CUDA build (~2.5 GB of wheels plus nvidia-* CUDA
# runtime libraries), producing a ~6 GB image and a 30-60 minute build. The
# agent layer needs none of that, so it lives in its own image.
#
# Floors below are the versions actually installed and working in the owner's
# Windows 3.11 venv as of 2026-08-09. Upper bounds appear only where a known
# breaking major boundary exists. Exact tested versions: requirements.lock.txt.

# Core
python-dotenv>=1.0
pyyaml>=6.0
pandas>=2.2
numpy>=1.26
scikit-learn>=1.4

# Agents / LLM routing (OpenRouter is OpenAI-API compatible)
#
# CrewAI 1.x is a breaking redesign of the 0.x API (crewai.LLM, crewai_core
# split, new Flow primitives). The <2.0 bound is deliberate: code in src/agents/
# is written against 1.x and would not run on 0.5x.
crewai>=1.15,<2.0
openai>=2.0,<3.0      # used as the OpenRouter client; 2.x broke 1.x call sites

# Dashboard
streamlit>=1.37

# Dev / test
pytest>=8.0
ruff>=0.5
pre-commit>=3.7
detect-secrets>=1.5

# Facial cues (Phase 28). Optional at runtime: src/media/facecues.py checks
# whether both import and, when either is missing, reads no face and says so on
# the page rather than failing. Kept in the BASE layer deliberately -- these are
# what the deployed Streamlit Community Cloud app installs, and neither pulls
# torch, which is what keeps the app inside its 2.7 GB memory ceiling.
#
# headless, not opencv-python: the full wheel links libGL, which is absent from
# the Community Cloud image and fails at import with a shared-object error that
# looks like a broken app rather than a missing system library.
hsemotion-onnx>=0.3
onnxruntime>=1.17
# <5 is load-bearing, not caution: OpenCV 5.0 removed cv2.CascadeClassifier and
# the bundled Haar cascade data, which is how the face is located here. With a
# 5.x wheel the import succeeds and the attribute does not exist, so the failure
# arrives at the point of use rather than at install time.
opencv-python-headless>=4.9,<5
# hsemotion-onnx declares a dependency on the NON-headless opencv-python with no
# upper bound. Both wheels install into the same `cv2` namespace, so an
# unconstrained 5.x pulled in as its dependency wins over a pinned 4.x headless
# and takes the cascade API away again. Pinning both is what actually holds.
opencv-python<5

# Press-conference transcripts (Phase 29). Reads the caption track a video
# already publishes: no video download, no audio, no pixels. Optional at
# runtime -- src/media/pressroom.py probes for it and refuses honestly when it
# is absent -- but listed here because the deployed app needs it.
youtube-transcript-api>=1.0
