into an interpretable 0–1 pre-competition risk index, with span-level evidence.

B2. THE 0.50 PROBLEM — read this before changing any input path
--------------------------------------------------------------------------------

LexiconBackend scores anything. Given keyboard mash, or an empty string from a
missing OCR engine, or a car-park sign: nothing matches, all ten probabilities
are 0.0, the weighted sum is 0.0, and the logistic squash returns an index of
EXACTLY 0.50 — a psychological score of 50/100 with a band, a stamp and ten
tiles under it. Every step is arithmetically correct. The screen is a lie.

Three components exist solely because of this one failure arriving by three
different doors:
  - gibberish.admit .................. the paste box
  - NullExtractor returning ok=False . the missing-backend door
  - mediaio re-running the text gate . OCR of something that is not prose

RULE FOR ANY FUTURE INPUT PATH: an input that cannot be read produces NO NUMBER.
Never a zero, never a default, never a midpoint.

--------------------------------------------------------------------------------
B3. THE FOUR STEPS OF THE MEDIA PATH
--------------------------------------------------------------------------------

  [1] admit the file      REFUSES   magic numbers + header parsing, pure Python
  [2] recover words       REFUSES   OCR (photo) / speech (video), if unreadable
  [3] admit the words     REFUSES   gibberish.admit, on machine-read text
  [4] judge the register  FLAGS     relevance.judge — advisory, never refuses

Steps 1–3 refusing means no DashboardView is constructed. Step 4 decorates.

STEP 1 — src/media/admission.py
  Pure byte parsing, NO image library (no Pillow, no opencv, no ffprobe),
  because the Phase 6 reproducibility property is that a reviewer runs the
  artifact with no install beyond the pinned requirements. Parses PNG, JPEG
  (walking marker segments, including 0xFF fill bytes — T.81 B.1.1.2, found by
  a fixture), GIF and WebP (all three sub-formats) dimensions; sniffs MP4/MOV
  and Matroska/WebM containers. Format comes from magic numbers, NEVER from the
  extension, so a zip named .jpg is refused.
  Refusals: empty, >64MB, <256 bytes, <64px short edge, >12000px, not media.
  DELIBERATELY DOES NOT judge picture content. See B4.

STEP 2 — src/media/extract.py
  OCR: the upstream Tesseract engine (Apache-2.0,
  github.com/tesseract-ocr/tesseract) invoked as a SUBPROCESS via the
  documented `tesseract stdin stdout` pseudo-filenames, at --psm 6 --oem 1
  -l eng. psm 6 ("single uniform block") because a photographed journal page is
  one block and the default psm 3 fragments a phone photo. oem 1 (LSTM only)
  because the default falls back to the legacy matcher whose traineddata modern
  distributions no longer ship.
  REMOVED in this phase: pytesseract and Pillow. pytesseract is a thin wrapper
  that shells out to the same binary after writing a temp file; Pillow existed
  only to feed it. Tesseract links Leptonica and decodes PNG/JPEG/TIFF/GIF/
  WebP/BMP itself, so nothing in this repository decodes an image.
  BUG FIXED: available() previously checked whether pytesseract and PIL could be
  IMPORTED. Both are pip packages that install cleanly on a machine with no OCR
  engine, so the check returned True on exactly the machines where OCR does not
  work, NullExtractor was never selected, and every upload showed a coach the
  string "TesseractNotFoundError". available() now runs the binary AND checks
  --list-langs. Missing language data is a third state with its own message.
  The engine build is recorded in MediaExtraction.method and rendered on the
  page, because a different build or psm returns different words and therefore a
  different score.
  Speech: faster-whisper (tiny, en), optional, absent in a clean checkout.

STEP 4 — src/media/relevance.py
  MEASURED, not asserted. Weights chosen on gold_dev (n=100), reported on
  gold_eval (n=400) which was untouched until the weights were fixed:
      recall, dev split ....... 0.820
      recall, HELD-OUT split .. 0.850   <- the figure that means something
      false positives ......... 1 of 20 authored negatives (0.05)
      threshold ............... 0.25, declared, not grid-searched
  Held-out recall ABOVE dev recall is the evidence it matched a register rather
  than memorising sentences; a test asserts the dev-to-eval gap never opens.
  Five declared terms: first-person rate +5.0 (dominant: 80% of corpus
  utterances vs 5% of negatives), sport vocabulary +0.25, self-state vocabulary
  +0.30, capitalisation share −1.0, digit share −4.0. The last two catch signage
  BY SHAPE, so an unseen sign still fails.
  ADVISORY. Off-register text is SCORED AND FLAGGED, on the owner's decision of
  2026-09-15. The flag renders above the score, outside any expander, in the
  error style, so it survives a screenshot.

--------------------------------------------------------------------------------
B4. THE NON-VERBAL CHANNEL — the most dangerous file in the repository
--------------------------------------------------------------------------------

src/media/nonverbal.py. The owner asked for face and voice analysis to move the
score. It is built and wired, held down four ways BY CONSTRUCTION:

 1. NonVerbalReading refuses construction without "NOT A MEASUREMENT" in its
    stamp — same mechanism as ScoreSurface/PROVISIONAL and
    BiosignalWindow/SIMULATED.
 2. nonverbal_context_weights() returns {} unless enabled=True is passed.
    Empty weights is the text-only path in fusion.score, so the risk index is
    BIT-IDENTICAL with and without an attached file. tests/test_media.py asserts
    equality, not approximate agreement. This is what lets the paper stay
    text-only while the page offers uploads.
 3. The default reader, SimulatedNonVerbalReader, derives three scalars from a
    SHA-256 of the file bytes. It DOES NOT LOOK AT A FACE. Deterministic so a
    screenshot reproduces.
 4. GatedRealReader — any reader that would look at a real face or voice —
    RAISES NonVerbalEthicsGate on construction. The blocker is a document, not
    a missing model, so it is not cleared by deleting the raise. See
    docs/ethics.md §13.5 for what must be true first.

Features are named expressivity / vocal_strain / steadiness — properties of a
SIGNAL, not states of a person. "Anxious face: 0.8" is a claim about someone;
"expressivity: 0.8" is a claim about pixels, and only the second is defensible.

WHY NO PICTURE CLASSIFIER. The owner clarified that "relevant" means images of
athletes and of press conferences. A visual classifier for that needs a labelled
image set, a held-out split and a reported error rate, none of which exist here.
A gate whose failure rate nobody knows, on the page whose entire design is about
not asserting unmeasured things, would be the most reviewer-visible
contradiction in the project. The register test judges WORDS instead, and can
therefore report a number. A photo of a face with no words in it yields nothing
and is refused — that is the honest boundary and it is stated as one.
