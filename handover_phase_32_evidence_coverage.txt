1. THE FEATURE IN ONE PARAGRAPH
--------------------------------------------------------------------------------
Every construct in this project is anchored to a validated sports-psychology
instrument. Ten constructs map to eight instruments. This widget projects one
scored text back onto those instruments and reports, per subscale, whether the
text gave evidence at all -- and, where it did not, says so plainly. Its output
IS the limitation. There is no reading of "somatic anxiety: SILENT" in which it
becomes a finding about a person.


2. WHY IT IS NOVEL (and what is merely reused)
--------------------------------------------------------------------------------
NEW TO THIS PROJECT AND, AS FAR AS THE OWNER AND THIS PLAN CAN TELL, TO THE
LITERATURE:

  N1  Instrument-space projection. `instrument_anchor` has sat in
      config/taxonomy.yaml since Phase 4 and has never been used as an analysis
      or display axis. Nothing in src/ reads it today.

  N2  Negative-space reporting. Every existing surface -- bars, atlas, risk
      index, explanation cards -- reports what was FOUND. Nothing reports what
      the input could not speak to.

  N3  Coverage-conditioned index. The risk index is currently rendered with no
      statement of how much evidence it rests on. This widget pairs it with its
      evidential denominator: "this index rests on 2 of 8 instruments."

  N4  Silent subscales as next questions. Each unevidenced subscale is rendered
      as a topic the reader could ask about. This converts a limitations display
      into something a coach can act on, and is the feature's product
      justification rather than only its honesty justification.

REUSED, NOT NEW -- do not claim these as contributions:

  -   The four-state ledger (evidenced / inert / silent / refused) is yesterday's
      src/evaluation/abstention.py::CAUSES. New here only in that it is surfaced
      per input, on screen, instead of aggregated in a report.
  -   ConstructBar.inert and .detected already exist and already carry the
      distinction. No new detection logic is required or permitted.
  -   Widget, theme.palette, the page-shell pattern, the stamp discipline.

THE ARGUMENT FOR THE PAPER (one sentence, and the thing worth writing up):
A questionnaire is administered -- every item gets answered. Text is volunteered
-- the athlete says what they say. A text-derived profile is therefore
structurally incomparable to a questionnaire profile, and text-based
psychological inference work elides this universally.

NOVELTY IS NOT YET VERIFIED. No literature search was run. Before any "first" or
"no prior work" claim reaches paper/, run the Phase 3 Literature Agent over:
selective prediction / abstention in ML; psychometric coverage and construct
under-representation; construct validity of text-derived measures; missing-data
reporting in psychological assessment. If prior work exists, the feature is still
worth shipping -- the claim just changes from "novel" to "first in this setting".


3. WHAT THE MOCKUP REVEALED (read before building -- it is the point)
--------------------------------------------------------------------------------
Real numbers from build_view() over gold_dev.jsonl and one Match-day scenario:

  Match-day scenario passage    3 constructs detected   2 of 8 instruments
  Richest single utterance      2 constructs detected   2 of 8 instruments
  Sparse utterance              1 construct  detected   1 of 8 instruments

A realistic passage speaks to a QUARTER of the instrument set. That is the
finding, and the widget's whole value is that it is undeniable on screen.

Consequence the owner has accepted: a reviewer seeing "2 of 8" beside a
confident risk index will ask why the index is shown at all. The answer is that
the index is a ranking over what WAS detected, and the widget is what makes that
scope explicit rather than implied. Do not soften the panel to dodge the
question.


4. ARCHITECTURE
--------------------------------------------------------------------------------
Copies the dashboard architecture exactly. Pure modules under src/dashboard/,
rendering separated from computation, page shell with zero business logic.

  config/instruments.yaml           NEW  instrument -> subscale -> construct,
                                         one citation per row. Mirrors the
                                         config/brain_atlas.yaml convention.
  src/dashboard/instruments.py      NEW  loads + validates + freezes that file
  src/dashboard/coverage.py         NEW  the ledger. Pure. No I/O, no Streamlit
  src/dashboard/coverage_panel.py   NEW  renderer. Theme-token driven, light+dark
  dashboard/pages/7_Evidence_coverage.py  NEW  page shell, renderer only
  src/dashboard/widgets.py          MOD  coverage_widget(view) -> Widget tile
  src/dashboard/copy.py             MOD  COVERAGE_PLAIN, COVERAGE_CAVEATS
  tests/test_coverage.py            NEW  the suite in sec.7
  docs/dashboard.md                 MOD  a section, as every feature gets
  docs/model_card.md                MOD  one paragraph under the Phase 11 pattern

A NEW RENDERER FILE, NOT neurovis.py. neurovis.py is 1364 lines. Adding to it
breaks the 800-line ceiling in the coding rules.

STATE DERIVATION -- this is the one design decision that matters:

  bar.detected == False              -> SILENT
  bar.detected and bar.inert         -> INERT
  bar.detected and not bar.inert     -> EVIDENCED
  no view was built (gate refused)   -> REFUSED (page shows the refusal, no table)

Derive from DashboardView.bars ONLY. Do NOT import src.evaluation.abstention.
The dependency direction would invert -- src.evaluation already depends on
src.dashboard, and yesterday an eager import in src/evaluation/__init__.py
tripped the OPEN-036 cycle and broke the suite. The two modules agree on the
four states by construction; sec.7 has the test that keeps them agreeing.

DOES NOT MOVE THE RISK INDEX. Read-only projection over an existing view. No
context mapping, no weights, no committed figure touched. Assert it.

6. RISKS AND THE GUARD FOR EACH
--------------------------------------------------------------------------------
  R1  COPYRIGHT -- do not reproduce instrument items.
      CSAI-2, ABQ, CD-RISC and TAIS are copyrighted instruments. Reproducing
      their item text is a licensing violation and it is the single most
      damaging mistake available in this phase.
      GUARD: the N4 "what to ask next" prompt is NOT an instrument item. Use the
      `definition` field already in config/taxonomy.yaml, which the project
      authored. A test asserts every prompt string is derived from taxonomy.yaml
      and that config/instruments.yaml contains no free-text item-like field.

  R2  READ AS ITEM-LEVEL COVERAGE.
      CSAI-2 has 27 items; this project carries one construct per subscale.
      "2 of 3" must never imply two thirds of a questionnaire was completed.
      GUARD: the string "subscales, not items" renders adjacent to every count,
      outside any expander. A test asserts its presence and asserts no item
      count is ever displayed.

  R3  SILENT READ AS ABSENT.
      Silent means one of: the construct is absent; the athlete did not mention
      it; the detector missed it. At a 20.2% silent rate the third is common.
      GUARD: copy is fixed at "this text gives no evidence either way", screened
      at import by the existing copy.py _screen() walk. A test asserts the panel
      never renders "no X", "free of X", "does not have".

  R4  COVERAGE MISTAKEN FOR CORRECTNESS.
      Evidenced means a cue fired, not that it fired correctly. Precision is
      unmeasured and needs the gold set (OPEN-025).
      GUARD: the caveat renders above the table, in the error style, outside any
      expander -- so it survives a screenshot. Same rule as CLAUDE.md sec.13.2.

  R5  DRIFT FROM abstention.py.
      Two modules defining the same four states will diverge.
      GUARD: the agreement test in sec.7. They must not import each other.

  R6  THE DEMO LEXICON IS UNEVALUATED.
      The live path runs the widened DASHBOARD_EXTRA_CUES, not the frozen
      evaluated list. Coverage shown to a visitor is coverage of an unevaluated
      detector.
      GUARD: carry the same disclosure docs/dashboard.md already makes. Do not
      quote a coverage percentage in the paper without saying which cue list
      produced it.

8. EXPLICITLY OUT OF SCOPE
--------------------------------------------------------------------------------
  -   Coverage aggregated across MULTIPLE texts from one athlete over time
      ("across 5 texts, ABQ has never been evidenced"). This is the natural
      next step and it is the temporal hook already in the project's Future
      Work. It is a second phase, not this one.
  -   Any attempt to SCORE a subscale rather than report its coverage state.
      The moment a subscale gets a number, this stops being a limitations
      display and becomes an unvalidated psychometric instrument.
  -   Reproducing, paraphrasing closely, or linking to instrument items. R1.
  -   Any change to detection, fusion, weights or the cue lists. The widget is a
      projection of an existing view and nothing else.

10. OWNER DECISIONS (locked 2026-09-22)
--------------------------------------------------------------------------------
  Q1  DECIDED: SHIP UNFLAGGED. No SRN_* environment variable, no conditional
      page registration. The page and the tile are always present.

      This is a deliberate departure from pages 3-5, which sit behind
      SRN_COGNITIVE_LAYER, and the reason the departure is safe is worth
      stating because a future reader will otherwise assume an oversight: the
      cognitive layer is flagged because it introduces SIMULATED signals a
      reader could mistake for measurements, and because a real physiological
      source behind that seam would be a different privacy class entirely
      (CLAUDE.md sec.11.2). This widget introduces no source, no signal, no
      sensor, no new dependency and no new number. It is a projection of a view
      the dashboard has already built and already shows. There is nothing for a
      flag to protect.

      Consequence to accept: every visitor sees "2 of 8" from the first load.
      That is intended. Do not add a flag later to hide it on a demo day.

  Q2  DECIDED: COMMITTED as the approved visual reference, the same role
      reports/cognitive_concepts.html plays for the brain atlas. It is the
      design contract for sec.5 STEP 3. Do not delete it when the real panel
      lands -- a later session needs to see what was approved, not infer it
      from the implementation it is supposed to be checking.

  Q3  STILL OPEN. Does the coverage tile go on the main dashboard grid by
      default, or only on its own page? Recommendation stands: BOTH, matching
      atlas_widget. Not blocking -- STEP 4 can build the page first and add the
      grid tile in the same commit once the owner confirms.
