PART B — WHAT THIS SESSION DID
--------------------------------------------------------------------------------
Decisions taken (confirmed by the owner before work started):
  1. Keep Streamlit as the shell. The animated surface is a self-contained HTML
     document mounted with st.components.v1.html, animated with motion.dev
     (https://motion.dev) loaded as an ES module from jsDelivr. A separate
     FastAPI + static frontend rewrite was considered and rejected as too large
     a change to the architecture this close to the paper.
  2. Register: written for a coach or athlete with no ML background. The
     technical vocabulary is not deleted, it is moved into a glossary so a
     reviewer can still map every plain phrase back to the paper's term.

Files created
  src/dashboard/copy.py
      Every plain-English caption on the page, as data. Ten constructs get an
      everyday name, a one-sentence meaning and a direction ("pushes the number
      up" / "pulls the number down" / "shown, but counted as zero"). Also
      HOW_IT_WORKS (four steps), the three headline-number explainers, section
      explainers and a 10-entry GLOSSARY covering construct, risk index,
      "not calibrated / ranking only", inert construct, span, unevidenced
      driver, lexicon baseline, macro-F1, the PROVISIONAL stamp and
      OPEN-011/021/025.
      HONESTY MECHANISM: _screen() walks this module's own namespace at import
      time and passes every string through assert_no_forbidden_language. A
      caption added next month is screened without anyone remembering to. This
      matters because view.render_text()'s screen never sees a caption the
      Streamlit shell writes itself, and a plain-English rewrite is the change
      most likely to smuggle back "accuracy" or an upgraded validation claim.

  src/dashboard/motion.py
      motion_panel(view)  -> the animated risk panel as one HTML document
      spans_panel(view)   -> the evidence list (which words triggered which signal)
      panel_height/evidence_height -> iframe heights (an iframe does not grow)
      Renders NO number the view does not already carry: it reads
      ConstructBar.probability/.contribution/.inert and nothing else, so it
      cannot disagree with the SVG figures beside it. Rows are ordered by
      absolute contribution (a demo is scanned top-down for "what drove this");
      charts.py keeps alphabetical order (a figure is scanned for a named row).
      Inert constructs keep all three redundant channels from charts.py — hatch
      fill, dashed outline, the literal word "inert". Animation is a fourth
      channel, never a replacement. prefers-reduced-motion is honoured, and a
      light-theme palette is supplied via prefers-color-scheme.
      Every emitted string is screened by assert_no_forbidden_language before
      it is returned.

DEFECT FOUND BY RENDERING, NOT BY THE SUITE (the Phase 20 lesson, again)
  The first build put everything — DOM construction and animation — inside one
  ES module script. Screenshotted with the CDN unreachable, the module never
  executed and the panel came back as an empty card while all 25 dashboard
  tests stayed green. Fixed by splitting: a classic <script> builds the rows and
  paints the final state with no imports, and the module script only animates
  from a start state it sets itself to the state already painted. A failed
  import now changes nothing a reader can see. This is the sixth instance of
  "the check and the thing it protects were related by assumption".
