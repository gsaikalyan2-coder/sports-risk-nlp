# Model Card — Phase 14 construct classifier

> **This model has no accuracy, and one has not been withheld — none exists.**
> It was trained on synthetic text against labels a generator planted, and
> `data/gold/` is empty (**OPEN-025**), so there is no human-verified evaluation
> set anywhere in this project. Every number below is a **corpus property** of
> `synth_precomp_v1`. None of them describes how well this model detects
> psychological constructs in athlete language, because no athlete wrote any of
> the text it has seen.

- **Status:** research artifact, Phase 14 of 25. Not fit for any use involving a
  real person.
- **Card version:** written at Phase 14, before the sweep was run. The
  *Results* section is populated from `reports/transformer.json`; the sections
  around it state what was true regardless of how the numbers came out, so a
  good result cannot quietly soften the caveats.
- **Owner:** Saikalyan, SRMIST.

---

## 1. Model details

| Field | Value |
|---|---|
| Architecture | Transformer encoder + multi-label classification head |
| Base checkpoint | `microsoft/deberta-v3-base` (default); `roberta-base` fallback |
| Task | Multi-label classification over 10 sports-psychology constructs |
| Objective | `BCEWithLogitsLoss` with per-construct `pos_weight`, capped at 10 |
| Decision rule | Per-construct sigmoid threshold, tuned on a validation slice |
| Output | 10 independent probabilities → a (possibly empty) label set |
| Implementation | `src/models/transformer.py` |
| Runner | `scripts/run_transformer.py` |
| Seeds | Python, NumPy and torch seeded; default 42 |
| License / release | Not released. See §8. |

The label space is the 10 constructs of `config/taxonomy.yaml` v2:
`appraisal_orientation`, `attentional_focus`, `burnout_signal`,
`cognitive_anxiety`, `coping_style`, `motivation_orientation`,
`perceived_stress`, `resilience`, `self_confidence`, `somatic_anxiety`.

The empty set is a valid prediction. Records containing no construct (logistics
talk, scheduling, pleasantries) are common in this corpus, and a rule forcing at
least one label would manufacture a false positive on every one of them.

---

## 2. Intended use

**Intended:** to answer one methodological question — *how much of the
`synth_precomp_v1` template grammar can a pretrained encoder recover across
held-out templates, and how much of that is memorisation?* The answer supports
the paper's dataset and methodology sections and the design of the real corpus
that Phase 15 depends on.

**Not intended, and not supported by any evidence produced here:**

- assessing, screening, diagnosing, or profiling **any real person**;
- any inference about a named athlete's mental health (`CLAUDE.md` §1 forbids
  this outright, and no result in this project could justify it);
- selection, ranking, or any consequential decision about an athlete;
- deployment in a coaching, clinical, medical, or employment setting.

Even after `data/gold/` is populated, this model would be **decision-support and
research tooling** and not a diagnostic instrument. The constructs are grounded
in validated *self-report* instruments (CSAI-2, ABQ, SDT); inferring them from
text is a different measurement with different error properties, and that
inference is itself the open research question, not an established method.

## 3. Training data

| Field | Value |
|---|---|
| Corpus | `data/raw/synth_precomp_v1` |
| Origin | **Fully synthetic**, generated by `src/ingestion/synthetic.py` |
| Size | 4,000 records → 3,888 after deduplication (112 duplicate texts collapsed, 0 ambiguous dropped) |
| Labels | `generation_spec.planted_constructs` — what the generator was *told* to write |
| Human verification | **None.** `data/gold/` is empty (OPEN-025) |
| Real athlete text | **None.** (OPEN-011) |
| Language | English |
| PII | None by construction; the de-identification pipeline runs regardless |

### Why the corpus is synthetic

Confirmed decision, `CLAUDE.md` §10, revisited and resolved at Phase 7
(2026-08-09). A survey found **no public corpus of pre-competition athlete
text**. Every athlete-speech corpus located is post-match, which is the wrong
side of the event for an anticipatory taxonomy — `appraisal_orientation` and
anticipatory `cognitive_anxiety` are defined by facing a competition that has
not happened yet. Four candidate sources were surveyed and all four rejected on
licensing or access grounds (`docs/data_sources.md` §4). The owner chose
synthetic-first and retained both the pre-competition framing and the full
taxonomy.

### What the labels are, precisely

They are the generator's intent. A record labelled `cognitive_anxiety` is one the
generator was instructed to build from a `cognitive_anxiety` template. **No human
read that text and judged that it expresses cognitive anxiety.** The distinction
matters because it caps what any score can mean: agreement with these labels is
agreement with a template bank, and a model that agrees with it perfectly has
learned the bank, not the construct.

`src/models/dataset.py` enforces this: `load_gold()` raises rather than falling
back to silver, and `load_silver()` requires an explicit
`acknowledge_no_signal=True` because the silver labels are PRNG output keyed on a
prompt hash (**OPEN-028** — no live OpenRouter call has ever been made,
OPEN-008).

## 4. Evaluation

### Splits

Two, and both are reported, because the gap between them is itself a result.

- **Template-disjoint** (the honest one) — templates are partitioned first;
  a record reaches the test side only if *every* template it uses is a test
  template, and straddlers are discarded. 2,591 train / 443 test / 854 discarded.
  0 templates shared. 0% exact text overlap.
- **Random** (a foil, never quoted alone) — 3,110 / 778. **149 templates appear
  on both sides**, 94.6% 4-gram overlap. A high score here measures memorisation.

This is **OPEN-012**, and Phase 13 measured it: TF-IDF + LinearSVC scores
**1.000** on the random split and **0.181** on the template-disjoint one. The
same collapse must be assumed to apply to this model until its own two numbers
are read side by side.

### Threshold tuning

Per-construct thresholds are tuned on a validation slice carved out of the
**training** records, never on test. The carve is itself template-disjoint
(`carve_validation` delegates to `template_disjoint_split`), so thresholds are
not calibrated on phrasings the model memorised and then applied to unseen ones.

*Limitation:* the slice is ~15% of training records, so for the rarest
constructs it is a few hundred examples. Thresholds for those are tuned on thin
data. A construct with zero validation positives keeps 0.5 rather than fitting
noise.

### Metrics

Macro-F1 is primary (`config/settings.yaml`), micro-F1 and per-construct P/R/F1
are secondary, all with 95% percentile bootstrap confidence intervals. Macro
rather than micro because the rare constructs matter as much as the common ones.
The macro denominator is always 10, even when a construct has no support —
shrinking it would raise the score by averaging over fewer constructs, which is a
real way papers overstate results.

### The Phase 13 bar (template-disjoint, planted labels)

| system | macro-F1 |
|---|---|
| lexicon | **0.462** ← the gate reference (OPEN-021 floor) |
| tfidf_logreg | 0.222 |
| memorisation_probe | 0.197 |
| tfidf_linearsvc | 0.181 |
| stratified_random | 0.104 |
| majority | 0.000 |

### Gate

`PROJECT_PLAN.md` Phase 14: *transformer > best baseline (macro-F1)*. Evaluated
on the template-disjoint split with a **paired bootstrap** significance test at
α = 0.05 — a point-estimate comparison would let the gate pass on noise.

**Passing would mean:** the near-synonym substitution layer produced realisations
varied enough that a pretrained encoder generalises across them where a
bag-of-ngrams model cannot. A fact about the corpus.

**Failing would mean:** the construct signal in this corpus is essentially the
cue words themselves. Also a fact about the corpus, also publishable, and **not**
to be tuned away — the quantity being optimised is agreement with a template
generator, so a higher number would not be a better model.

Neither outcome bears on `CLAUDE.md` §9 publication-readiness, which requires a
human-verified gold set that does not exist.

## 5. Results

Run 2026-08-11, `distilroberta-base`, 6 configurations, torch 2.13.0+cpu /
transformers 5.15.0, seed 42. Source: `reports/transformer.json`.

| | value |
|---|---|
| Best configuration | `distilroberta-base`, lr 2e-5, batch 16, 6 epochs, len 128 (best epoch 5) |
| macro-F1, template-disjoint [95% CI] | **0.588** [0.549, 0.624] |
| macro-F1, random split | 0.905 |
| Gap (memorisation indicator) | **+0.317** (TF-IDF+LinearSVC gapped +0.819) |
| micro-F1 / subset accuracy | 0.614 / 0.339 |
| Reference (`lexicon`) | 0.462 |
| Δ vs reference, paired bootstrap p | **+0.126**, p = 0.000 |
| Gate | **PASS** |
| Train / validation split | 1,679 / 355 records |

### Full sweep, template-disjoint

| configuration | tuned macro-F1 [95% CI] | untuned (0.5) | Δ |
|---|---|---|---|
| lr2e-5, bs16, **ep6** | **0.588** [0.549, 0.624] | 0.616 | −0.028 |
| lr3e-5, bs16, ep4 | 0.582 [0.546, 0.615] | **0.639** | −0.058 |
| lr2e-5, bs16, ep4 | 0.558 [0.525, 0.590] | 0.602 | −0.044 |
| lr2e-5, bs8, ep4 | 0.546 [0.496, 0.586] | 0.593 | −0.047 |
| lr1e-5, bs16, ep4 | 0.504 [0.466, 0.537] | 0.518 | −0.014 |
| lr5e-5, bs16, ep4 | 0.500 [0.460, 0.537] | 0.613 | −0.112 |

The top three configurations have heavily overlapping confidence intervals
(0.588 / 0.582 / 0.558). They are not meaningfully distinguishable on 443 test
records, and the sweep should be described as "no configuration clearly
dominated" rather than as having identified a winner.

### Threshold tuning made results **worse**, on every configuration

The `Δ` column above is negative six times out of six, by between 0.014 and
0.112. Per-construct thresholds fitted on the 355-record validation slice cost
held-out macro-F1 rather than buying it — the tuning was fitting validation
noise, exactly the risk flagged in §4 before the run.

The consequence is concrete: the best *untuned* result (0.639, lr3e-5) beats the
best *tuned* result (0.588) by 0.051.

**This is a finding, not a bug**, and it should be reported as one: on a corpus
of this size, per-construct threshold optimisation degrades generalisation across
held-out templates. It also argues for dropping the 10 tuned parameters entirely
and reporting at a fixed 0.5 — which both improves the number and removes free
parameters, the rare case where the more conservative choice is also the better
one. See §7 item 9 for the caveat on making that switch after seeing the result.

See `reports/transformer.md` for the per-construct breakdown and the full sweep
table, and `logs/transformer_*.json` for one run log per fitted configuration.

## 6. Hyperparameters and the sweep

Defaults: learning rate 2e-5, batch size 16, 4 epochs, max length 256, weight
decay 0.01, warmup ratio 0.1, validation fraction 0.15, `pos_weight` cap 10,
seed 42. Epoch selection is on validation **macro-F1**, not validation loss —
on an imbalanced multi-label problem the lowest-loss checkpoint is often not the
best-macro-F1 one, and macro-F1 is the declared primary metric.

The sweep is 6 configurations (learning rate ∈ {1e-5, 2e-5, 3e-5}, batch size ∈
{8, 16}, plus a longer run and a shorter sequence length). Deliberately small:
every additional configuration is another chance to select the one that happened
to suit this test split, and the quantity being optimised is not one the paper is
allowed to call accuracy. The best configuration was selected on the test split,
so the reported best is **mildly optimistic**; with 6 configurations the bias is
small but it is not zero and is stated here rather than omitted.

## 7. Known limitations

1. **No real athlete text** (OPEN-011). The project's highest live risk.
   Contribution #1 — the construct-grounded corpus — depends on it. Domain shift
   from template English to real pre-competition speech is unmeasured and should
   be expected to be large.
2. **No human-verified labels** (OPEN-025). No inter-annotator agreement, no
   accuracy, no calibration against human judgement.
3. **Template memorisation** (OPEN-012). Demonstrated at 1.000 → 0.181 for the
   linear baseline. Any number from a random split is uninterpretable alone.
4. **Silver labels contain no signal** (OPEN-028/OPEN-008). They are PRNG output;
   they were not used to train this model and must not be.
5. **Thin threshold-tuning data** for rare constructs (§4).
6. **Test-split selection bias** from the sweep (§6).
7. **Construct validity is assumed, not established.** The constructs come from
   validated *self-report* instruments. That a text expresses a construct, and
   that a person scores highly on its questionnaire, are different claims. This
   project has evidence for neither yet.
8. **English only. One generator. One seed corpus.**
9. **The "drop threshold tuning" conclusion was reached after seeing test
   results** (§5). Choosing a decision rule because it scored better on the test
   split is a form of selection on test, even when the chosen rule has *fewer*
   free parameters. Two things make it defensible and both should be stated
   rather than assumed: the direction of travel is toward fewer parameters, not
   more, and the effect is consistent across all six configurations rather than
   resting on one. The honest way to report it is as an observation about this
   corpus — "per-construct tuning degraded held-out macro-F1 in every
   configuration we ran" — not as a tuned-away improvement to the headline
   number.
10. **The best configuration was selected on the test split** and the top three
    configurations' confidence intervals overlap heavily, so "best" here means
    "highest point estimate", not "significantly better than the others".

## 8. Ethics

Risk labels applied to people can stigmatise, and "elevated psychological risk"
attached to a named athlete could affect selection, contracts, or reputation.
`CLAUDE.md` §1 and `docs/ethics.md` govern; the binding points for this artifact:

- **No inference about any real, named person.** Not by this model, not from its
  outputs, not as an illustrative example in the paper.
- **Research and decision-support framing only**, never diagnosis.
- **Not released as a downloadable checkpoint.** A checkpoint that predicts
  "burnout risk" from text, released without a validated evaluation, would be
  used on real people regardless of what its card says. Weights stay in-repo
  under `models/`; the *code* is what gets released.
- The de-identification pipeline runs on any real text before it reaches any
  model, even though the current corpus is synthetic.
- Misuse potential, bias, and limitations must appear in the paper, not only
  here.

## 9. Reproducibility

Phase 22 replaced an informal claim here with a declared, checked one. The full
path, its tiers, and everything it cannot reproduce are in
[`docs/reproducibility.md`](reproducibility.md); the machine-readable form is
`src/reproducibility/manifest.py::PLAN` and the checker is
`python scripts/run_reproduction.py`.

**Install the locks, not the floors.** `requirements-base.txt` and
`requirements-ml.txt` carry version *floors*, and a floor resolves to a
different answer on every build. The auditable files are the per-layer locks:

```bash
# light layer -- corpus, baselines, rescoring, dashboard. No torch.
pip install -r requirements-base.lock.txt

# training layer. The extra index is NOT optional: torch is pinned to
# 2.13.0+cpu, a PEP 440 local version that exists on no default index.
pip install -r requirements-ml.lock.txt \
    --extra-index-url https://download.pytorch.org/whl/cpu

python scripts/run_baselines.py --seed 42       # establishes the bar
python scripts/run_transformer.py --dry-run     # plan; no torch, no weights
python scripts/run_transformer.py --sweep       # the real run
```

**Verified 2026-08-24** by cloning the tracked tree into a new directory on a
different operating system, with no `data/` and no `models/`, and running tiers
A and B end to end. Every headline number came back at full float precision:
transformer template-disjoint macro-F1 0.5877114720181955, the +0.1259828877582358
delta over the lexicon floor, the +0.23423985163237282 split gap, and the
bootstrap interval bounds. `records.jsonl` and `utterances.jsonl` matched by
SHA-256.

Two things that check found, both now fixed and both worth a reviewer's
attention:

* **The tier-B path reads `reports/predictions/`, which is committed.** So a
  fresh clone re-derives the transformer's *scores* in seconds without torch,
  weights or corpus — and does not re-derive the transformer. Retraining is
  tier C, roughly ten CPU-hours, and is reported separately so a cheap green
  tick cannot stand in for it.
* **`utterances.jsonl` was not byte-identical across platforms** before this
  phase. The owner's copy carried CRLF and a container-generated corpus carried
  LF — identical content, 9,302 bytes apart, produced two days apart on two
  machines with nothing recording which. The pipeline writers now pin
  `newline="\n"`.

Each fitted model persists `manifest.json` beside its weights, carrying the seed,
torch and transformers versions, the resolved base checkpoint, the full
hyperparameter set, the tuned thresholds, the per-epoch validation curve, and a
SHA-256 **training fingerprint** over the exact `(record_id, text, label set)`
triples. The fingerprint function is shared with the classical baselines, so a
transformer run and a baseline run over the same data produce the same
fingerprint and can be *proven* to have trained on the same pairs.

Bit-exact reproducibility across different hardware is not claimed and is not
achievable for floating-point training. Same machine, same seed, same numbers is.

Pretrained weights are the one step that needs the network. If they cannot be
reached, `resolve_base_model` raises `WeightsUnavailable` and **refuses to fall
back to random initialisation** — a randomly-initialised encoder trains without
complaint and produces a low score indistinguishable, in this report, from the
honest finding that the corpus has no generalisable signal.

**The scoring model is unchanged.** The construct layer, the fusion layer, the
polarity policies and the explanation layer are byte-for-byte the same as

### 11.2 Register gate — measured behaviour

The only new component in this phase that produces a judgement, and therefore
the only one that owes a number.

| Quantity | Value | Basis |
|---|---|---|
| Recall, development split | 0.820 | `gold_dev.jsonl`, n=100. The split the weights were chosen on. |
| **Recall, held-out split** | **0.850** | `gold_eval.jsonl`, n=400. Not consulted until the weights were fixed. |
| False positives | 1 of 20 (0.05) | Authored negatives, `tests/test_relevance.py::NEGATIVES` |
| Decision threshold | 0.25 | Declared, not grid-searched. See below. |

Held-out recall above development recall is the evidence that the gate matched a
register rather than memorising the development sentences.
`tests/test_relevance.py` asserts the dev-to-eval gap never opens, because a
collapse there is the signature of a fitted threshold.

**Features and weights**, all declared rather than fitted, in the tradition of
`src/risk/fusion.py`:

| Term | Weight | Note |
|---|---|---|
| First-person rate | +5.0 | Dominant. 80% of corpus utterances vs 5% of negatives. |
| Sport vocabulary (saturating at 3) | +0.25 | Small: a large weight makes this a topic detector. |
| Self-state vocabulary (saturating at 3) | +0.30 | Overlaps the construct lexicon. See 11.3. |
| Capitalisation share | −1.0 | Catches signage by shape, not by word list. |
| Digit share | −4.0 | As above. |

### 11.3 Limitations of the register gate

1. **The negative set is authored by this project.** Twenty texts written for the
   test. The 0.05 figure is therefore a sanity check against plausible off-topic
   writing, not an estimate of behaviour on whatever a user uploads. This is the
   weaker half of the evaluation and it is weak in a way more data would fix.
2. **The positives are synthetic.** OPEN-011 applies unchanged: the register
   being matched is the register this project's generator writes, which is a
   hypothesis about how athletes talk rather than an observation of it.
3. **The gate is not independent of the thing being measured.** `STATE_WORDS`
   overlaps the construct lexicon, so a text can score as on-register partly
   because it is strained. The overlap is declared rather than engineered away,
   because a register test blind to self-state language would not be testing the
   register. `tests/test_relevance.py` asserts the overlap still exists, so it
   cannot quietly stop being true.
4. **One known false positive**, named rather than special-cased: "Our offices
   will be closed on Monday and will reopen on Tuesday morning" carries a
   first-person plural and a weekday, which is most of what the gate looks for.
5. **The gate does not refuse.** Off-register text is scored and flagged. A
   reader who ignores the flag gets a number that is arithmetically correct and
   is not a reading of an athlete.

### 11.4 OCR and speech recognition — provenance

Words recovered from a file carry a `MACHINE-READ` stamp and are never presented
as something a person typed.

* **OCR**: the Tesseract engine (Apache-2.0, `tesseract-ocr/tesseract`), invoked
  as a subprocess at `--psm 6 --oem 1 -l eng`. Not vendored, not wrapped. The
  engine build is recorded in `MediaExtraction.method` and rendered on the page,
  because a different build or segmentation mode returns different words and
  therefore a different score. Cited as `Smith2007`.
* **Speech**: `faster-whisper` (`tiny`, English), optional and absent in a clean
  checkout. Cited as `Radford2023`.
* **Neither is evaluated by this project.** No word-error rate is reported here
  and none should be quoted from here. Recovery is imperfect and the page says
  so above every recovered passage.
* **An absent backend reports absence, never an empty string.** This is a
  correctness property, not a nicety: an empty string scores 0.50 through the
  logistic squash, so a missing OCR engine would otherwise yield a confident
  mid-scale reading of a file nobody could read.

### 11.5 The non-verbal channel

Reported here for completeness and because its absence from the numbers is
itself a claim.

* Emits `expressivity`, `vocal_strain`, `steadiness`, each in [0, 1], named for
  properties of a signal rather than states of a person.
* Enters `LinearRiskScorer.context` with `context_weights={}` by default, which
  is the text-only path. `tests/test_media.py` asserts the risk index is
  **bit-identical** with and without an attached file.
* The default reader is `SimulatedNonVerbalReader`, which derives its values from
  a digest of the file bytes and **does not look at a face**. Its stamp carries
  `NOT A MEASUREMENT`.
* `GatedRealReader` — any reader that would look at a real face or voice —
  raises on construction. See `docs/ethics.md` §13.5 for what must be true first.
* **No number in this card, in any table, or in the paper was produced with this
  channel switched on.**

## 12. Phase 28 — the facial-cue channel (added 2026-09-16)

Supersedes §11.5. The channel described there was off by default and simulated;
it is now on, under consent, when a real face is found.

### 12.1 What it is

| | |
|---|---|
| Engine | `hsemotion-onnx`, model `enet_b0_8_va_mtl` (Apache-2.0) |
| Reference | Savchenko et al., *IEEE Trans. Affective Computing*, 2022; HSEmotion / EmotiEffLib |
| Face location | OpenCV Haar cascade `haarcascade_frontalface_default.xml`, largest face |
| Outputs used | `negative_valence`, `arousal`, each rescaled to [0, 1] |
| Weights into the index | `negative_valence` +0.20, `arousal` +0.10 — **declared, not fitted** |
| Runs when | The uploader affirms consent AND a face of at least 64 px is found |
| Otherwise | Simulated reading shown at weight 0; the reason is stated on the page |

### 12.2 Measured behaviour — none, and that is the claim

**No error rate for this channel has been measured by this project.** There is no
labelled image set here, no held-out split, and no outcome to validate against,
so nothing in this card reports how often the engine's cues are right about
anything. The upstream engine's published benchmarks are on AffectNet and the
ABAW challenge data, which are not athletes, not pre-competition, and not this
pipeline; they are cited as provenance for the engine and are not transferred
here as a claim about this system.

Consequently: every face-derived number on the page is qualified by the
limitation in `docs/ethics.md` §14.3, and no face-derived number appears in any
table or figure in this card or in the paper.

### 12.3 Known limitations

* **An expression is not a state of mind.** The affective-science literature does
  not support a reliable configuration-to-state mapping across people, contexts
  and cultures. A competitor mid-effort looks strained for reasons unrelated to
  coping.
* **The face detector is old and frontal.** A Haar cascade misses profiles,
  heavy occlusion and unusual lighting, and its miss rate here is unmeasured. A
  miss produces no number, which is the safe direction.
* **"Largest face" is a heuristic.** In a crowd scene the subject is assumed to
  be the nearest face. A wrong face yields a reading attributed to the wrong
  person, which is why the limitation text disclaims individual-level use.
* **Demographic performance is unknown.** Face analysis models are documented to
  vary across skin tone, age and sex. This project has measured none of that for
  this engine, and the channel must not be described as fair or unbiased.
* **The weights are a prior.** +0.20 and +0.10 were chosen by hand to be small.
  They are not learned, not tuned, and not validated.

## 13. Phase 32 — evidence coverage (added 2026-09-22)

A reporting surface, not a model change. Nothing in §1, §3, §5 or §6 is
affected: no weight, threshold, cue list or checkpoint moved, and the risk index
is bit-identical with and without it (`tests/test_coverage.py`).

**What it reports.** For one already-scored text, which of the eight validated
instruments behind the taxonomy that text gave any evidence about. Each
construct is a subscale of exactly one instrument
(`config/instruments.yaml`, every citation resolving in `paper/refs.bib`), and
each is reported as *evidenced* (a cue fired), *inert* (detected, then weighted
zero by the polarity policy) or *silent* (no evidence either way). The states
are read off `ConstructBar.detected` and `.inert`; no new number is computed.

**Coverage is not correctness.** Evidenced means a cue fired, **not that it
fired correctly**. Precision per construct is unmeasured and remains so until
`data/gold/` is annotated (OPEN-025). A coverage count is therefore a statement
about what the *input* contained, never about how well the detector performed,
and never about the person who produced the text.

**Silent is not absence.** It covers three cases — the construct genuinely
absent, the athlete not raising it, or the detector missing it — and Phase 31
measured a 20.2% no-detection rate over the corpus, so the third is common. No
surface may render silent as "no X", "free of" or "does not have"; asserted.

**What the numbers rest on.** The corpus is synthetic (OPEN-011) and the live
dashboard path uses `CONSTRUCT_CUES` widened with `DASHBOARD_EXTRA_CUES`, which
is not the frozen list the evaluation in §4–§5 uses. Over `gold_dev` a passage
speaks to fewer than two of eight instruments on average and none reaches all
eight. **No coverage figure may appear in the paper without naming the cue list
that produced it.**

**Instrument items are not reproduced.** CSAI-2, the ABQ, CD-RISC and TAIS are
copyrighted. This project maps to them and does not implement them; the
reader-facing prompts are derived from this project's own `definition` field in
`config/taxonomy.yaml`, and `config/instruments.yaml` has a closed field set so
it cannot acquire item text.
